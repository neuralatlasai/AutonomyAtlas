\section{Testing relevance and influence rather than retrieval alone}\label{sec:C33:05}
A memory can be retrieved and still have no appropriate effect on behavior. Suppose a user's prior instruction says that externally shared reports must omit a confidential appendix. A later request asks for a concise project update without explicitly mentioning confidentiality. A memory test that asks what the confidentiality instruction was measures explicit recall. The operational test asks whether the agent applies it when preparing the report. InMind's distinction between explicit recall and implicit application motivates this separation, while memory-writing and consolidation systems such as RecMem address different parts of the lifecycle~\cite{inmind2026,dai2026recmem}.

An influence experiment can intervene on a memory while holding the current task and evidence fixed. Compare a valid relevant instruction, an irrelevant record, a superseded instruction, and an adversarially injected instruction. The desired policy responds differently to these cases. Measuring only whether any memory was used rewards over-influence. Measuring only answer accuracy can hide an unauthorized disclosure that does not affect the nominal answer key.

The evaluation unit should be a user or organizational task stream with declared persistence. Freeze the post-history memory before testing explicit recall and implicit application so that the first test does not teach the answer to the second. Randomize task order or use independent cloned states. Preserve the exact accessible evidence and authority epoch. These controls distinguish a useful memory mechanism from leakage through the evaluation conversation.

The deployment architecture also needs a correction path. When a user disputes an answer, the system should identify whether the error came from source truth, retrieval, conflict resolution, context packing, model interpretation, or output attribution. Updating the answer text alone may leave the faulty derived memory intact. A correction should invalidate the appropriate descendants and record the reason, while avoiding a global overwrite that destroys legitimate historical information.
